# Project results

All generated evaluation outputs are stored under this directory and grouped by
model or analysis family. Experiment code, plans, and configurations remain under
`experiments/`.

## Layout

- `ML/` — classical ML and heuristic metrics, fold summaries, and plots.
- `ML/classical_studies/` — generated classical study runs; local-only.
- `LLM/` — generated language-model runs; local-only.
- `hybrid/` — generated cross-model ensemble predictions and metrics; local-only.
- `transformer/` — transformer study outputs, reports, and the small DNS audit
  fixtures used by regression tests.
- `transformer/tables/` — compact transformer result tables and figures, separated
  from experiment code and generated run directories.
- `final_summary/`, `embeddings_context/`, `per_model_targets/`,
  `revision_features/`, and `vote_weights/` — compact project analysis summaries.
- `annotation/` — local annotation exports and row-level labels; never publish.

Large checkpoints, fitted models, matrices, row-level predictions, generated run
directories, detailed governance exports, local annotation data, and derived corpus
files are intentionally excluded from Git. They stay on the local machine and can be
regenerated by workflows in `experiments/`, `models/`, and `scripts/`. Compact summary
metrics, reports, test fixtures, and publication figures remain available in the
repository. The row-level prediction-complementarity tables in
`transformer/tables/` and experiment manifests containing row-level data are also
local-only because they contain per-record identifiers or labels.

Do not copy private labels, reviewer mappings, credentials, or sealed evaluation
data into a public result export. Before publishing additional outputs, review
them for sensitive text and ensure that they do not expose reserved-set results.

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
Natural-language protocol specifications can permit several plausible implementations even when they use the normative keywords of BCP~14. \system{} is a revision-aware corpus, annotation workflow, modeling pipeline, and local review prototype for ranking potentially ambiguous Internet-Draft clauses using only information available at the evaluated revision, with draft-family-isolated evaluation. The corpus contains 253 draft revisions, 12 RFCs, and 31 verified technical errata. Labels form an operational reference built from three-model consensus and manual conflict verdicts; clauses labeled ambiguous are called \emph{reference positives}. On the 2,425-row classical cohort (160 reference positives, 6.60\% prevalence), engineered features plus TF--IDF give AP 0.3584 (Linear SVM), 0.3363 (random forest), and 0.3265 (logistic regression); twelve past-only revision features do not improve AP. On the 2,143-clause, nine-family reviewed-label cohort (138 reference positives), an ECDF ensemble of two DeBERTa variants reaches AP 0.6736, versus 0.5823 and 0.5761 for its components, with overlapping intervals. A supplementary routing analysis on 2,096 prediction-aligned clauses (109 positives) routes 79.0\% of clauses away from the LLM; hybrid AP/F$_2$ are 0.330/0.457 versus 0.372/0.447 for LLM-only, but paired intervals do not establish non-inferiority, and LLM responses were simulated from cached scores. These are development results: labels are not independent expert gold, and TCP and DNS are no longer untouched holdouts. Explanation quality was not evaluated. Private annotation exports, model weights, and large run artifacts are not in the released repository, so not every table can be regenerated. \system{} is a review-prioritization aid, not an ambiguity judge.

\noindent\textbf{Keywords:} Internet-Drafts, RFC, ambiguity detection, protocol specifications, natural language processing, DeBERTa, document evolution, leakage control.

\chapter{Introduction}

\section{Background and Problem Statement}

The Internet Engineering Task Force (IETF) develops protocols through sequences of mutable Internet-Drafts before stable RFC publication. Although capitalized terms such as \emph{MUST}, \emph{SHOULD}, and \emph{MAY} have defined meanings under BCP~14~\cite{rfc2119,rfc8174}, their surrounding prose can still leave actors, conditions, references, failure behavior, or interactions under-specified. Multiple standards-conforming interpretations can then produce interoperability defects or security-relevant implementation differences.

Prior systems show that protocol prose can be analyzed automatically. SAGE combines semantic parsing and author clarification to disambiguate RFC text and generate code~\cite{yen2021sage}. NRFCKG represents protocol requirements as a knowledge graph and searches for contradictions~\cite{feng2023nrfckg}. Most directly, RFCScope derives seven logical-ambiguity subtypes from verified errata and uses an LLM pipeline to find ambiguities in published RFCs~\cite{pawagi2025rfcscope}. These systems motivate automated support, but they do not answer a different operational question: \emph{could a risky clause have been prioritized while it was still an Internet-Draft, using only information available at that time?}

\section{Motivation}

That question introduces three hazards. First, a final RFC, later revision, or later erratum is an informative label source but an invalid prediction-time feature. Second, clause-level random splits place nearly identical text from the same revision lineage on both sides of an evaluation. Third, the positive class is rare, so accuracy and even ROC area can obscure poor retrieval of ambiguous clauses; precision--recall analysis is more informative under skew~\cite{davis2006pr,saito2015pr}.

\section{Aim, Objectives, and Research Questions}

This report presents a development-stage study of \system. Its central design principle is separation: source collection, structural parsing, revision alignment, candidate construction, annotation, model input, model selection, reserved validation, and sealed testing are distinct, hash-recorded stages. The intended output is not an automatic declaration that a standard is defective. It is a ranking that helps an author or reviewer allocate attention.

Throughout, the \emph{operational reference} is the project's binary annotation artifact, and \emph{reference positives} are the clauses it labels ambiguous. Metrics measure agreement with this reference, not universal ambiguity-detection accuracy.

The project evaluates the five research questions defined in the approved proposal:

\begin{enumerate}[label=\textbf{RQ\arabic*:},leftmargin=*]
  \item How effectively can ambiguous requirements be detected in historical Internet-Drafts using only information available at the evaluated draft version?
  \item Do contemporaneous revision-history and cross-reference features improve $F_2$, PR-AUC, and calibration over text-only models?
  \item How do heuristic, classical ML, fine-tuned transformer, LLM-only, and hybrid approaches compare in effectiveness, reproducibility, latency, cost, and review workload?
  \item Can hybrid routing preserve or improve detection effectiveness while reducing LLM calls relative to an LLM-only approach?
  \item How faithful and useful are the evidence spans, ambiguity subtypes, and explanations produced by the LLM verifier?
\end{enumerate}

The proposal also stated four hypotheses: revision-history features would improve $F_2$ and PR-AUC; hybrid routing would retain effectiveness while reducing LLM use; evidence grounding would reduce unsupported explanations; and random clause splitting would be more optimistic than family/temporal splits. This report distinguishes tested, partly tested, and untested claims rather than treating implementation as confirmation. RQ4 is addressed by an exploratory routing simulation in Section~\ref{sec:routing-results}; RQ5 remains deferred because explanation quality was not evaluated (Appendix~A).

\section{Scope and Contributions}

The contributions are:

\begin{itemize}
  \item A revision-aware corpus covering 253 draft revisions, 12 RFCs, and 31 verified technical errata, with future-information guards.
  \item A reproducible annotation workflow spanning eleven draft families, with explicit consensus rules, source provenance, and temporal-information controls.
  \item Matched-cohort evaluation of classical classifiers and a deterministic heuristic, plus separate leave-one-family-out comparisons of lexical, engineered, embedding, contextual, and revision-history features.
  \item Separate, auditable studies of local Qwen prompting and lexical/semantic hybrids, and a hash-pinned target-only DeBERTa-v3-base comparison on the reviewed-label cohort.
  \item An accounting of protocol corrections and blocked or incomplete study lines, so null and unavailable evidence is not silently omitted.
  \item Family-isolated OOF, nested threshold, family-robustness, and fixed-review-budget analyses, reported without conflating their distinct data artifacts.
  \item An explicit claim boundary, stated once in Section~\ref{sec:limitations}: labels are not adjudicated expert gold, and the proposal's TCP/DNS holdouts were consumed by the latest all-family reruns.
\end{itemize}

The scope is binary clause-level prioritization for human review. It excludes autonomous standards certification, automatic protocol implementation, and claims that the absence of an erratum proves clarity. The completed experiments are development studies over several explicitly separated annotation snapshots, and no independently sampled expert-gold test set was completed.

\chapter{Background and Literature Review}

\section{Ambiguity in Requirements and Protocol Text}

Ambiguity detection in requirements engineering includes lexical/rule-based indicators, supervised classifiers, and contextual language models. TAPHSIR combines machine learning for anaphoric-ambiguity detection with a BERT-based resolution component~\cite{ezzini2022taphsir}; a recent hybrid requirements study combines ambiguous-phrase rules with conventional classifiers~\cite{izhar2025ambiguity}. These systems demonstrate complementary roles for interpretable cues and learned representations. Their metrics are not transferable to Internet-Drafts, however, because ambiguity definitions, annotation units, prevalence, and document-family dependencies differ. In protocol text, a phrase can be lexically vague yet harmless under a surrounding state machine, while a precise-looking clause may still omit an actor, boundary, or conflict-resolution rule.

Protocol specifications add domain structure: packet fields, state transitions, normative strength, cross-references, and compatibility requirements. SAGE converts selected RFC prose to logical forms, asks humans to resolve remaining alternatives, and generates protocol code~\cite{yen2021sage}. PROSPER uses LLMs to extract protocol state machines from RFC text and diagrams~\cite{sharma2024prosper}. NRFCKG targets direct and conditional contradictions using extracted entities, rules, and constraint solving~\cite{feng2023nrfckg}. These systems address important neighboring problems. Formalization and contradiction checking can establish specific logical properties, but they do not by themselves prioritize ordinary draft clauses for human ambiguity review.

RFCScope is the closest conceptual predecessor. It analyzes 273 verified technical errata, defines seven subtypes under inconsistency and under-specification, and uses context construction, semantic partitioning, subtype-aware LLM analysis, and validation. Its evaluation reports 31 new ambiguities in 14 of 20 RFCs, including author-confirmed cases~\cite{pawagi2025rfcscope}. We use its subtype vocabulary as conceptual guidance, not as an automatic label oracle. Our prediction-time unit is a clause in a historical draft revision; our binary operational question is whether an ordinary implementer could reasonably derive materially different implementation behavior from the available text. \section{Document Evolution and Leakage-Aware Evaluation}

Scientific-writing resources such as arXivEdits and CASIMIR model document change through aligned versions and edit categories~\cite{jiang2022arxivedits,tinnes2024casimir}. Protocol specifications share the need to represent insertions, deletions, moves, splits, and merges, but a change is not itself evidence of ambiguity: revisions also contain editorial cleanup, new functionality, and terminology updates. We therefore separate \emph{correspondence} from \emph{ambiguity}, measure alignment coverage separately from label quality and detector performance, and never use the final RFC or a future revision as a detector input.

Evaluation must also respect the intended use. If the goal is transfer to a protocol family not seen during fitting, random clause-level splits are optimistic because clauses, templates, and lineages recur. Family-grouped evaluation is therefore more relevant than random splits, although it estimates transfer only over observed families and cannot substitute for a prospective test. Under rare-positive labels, average precision and precision--recall curves are more informative than accuracy alone~\cite{davis2006pr,saito2015pr}. Our contribution relative to prior work is not a new general ambiguity taxonomy; it is an end-to-end draft-stage study that makes temporal availability, family isolation, candidate selection, source-label artifacts, and evaluation cohorts explicit.

\section{Models for Imbalanced Text Classification}

The reviewed-label experiment compares two target-only \texttt{microsoft/deberta-v3-base} classifiers and an equal-weight rank ensemble on one frozen cohort. DeBERTa-v3 uses replaced-token detection and gradient-disentangled embedding sharing~\cite{he2023debertav3}. Focal loss emphasizes hard examples under class imbalance~\cite{lin2017focal}. The partial model freezes embeddings, the shared backbone, and layers 0--7, and trains layers 8--11, the pooler, and classifier. The classical and local-Qwen/hybrid studies are reported separately because they were evaluated under different data and validation protocols.

\subsection{Collection and structural parsing}

The curated corpus covers application, DNS, routing, security, and transport standards. Twelve RFCs and all available histories for eleven draft families are stored; OSPFv2 and BGP-4 are RFC-only because their historical drafts are not available through the same archive. The audit reports 253 expected and present draft revisions, 12 expected and present RFCs, and 31 verified technical errata.

The parser accepts both Datatracker plaintext and XML2RFC. It emits a common document--section--block tree while retaining original text, section paths, source locations, reference targets, tables, artwork, and formal syntax. A deterministic clause layer conservatively separates prose and list items. It recognizes uppercase BCP~14 keywords while guarding quoted text, references, abbreviations, version numbers, URLs, and condition--requirement pairs. Each clause receives a stable identifier and one of \textsc{Normative}, \textsc{Contextual}, \textsc{Excluded}, or \textsc{Manual Review}. This stage identifies likely requirements; it does not decide ambiguity.

\subsection{Local RFC-review prototype}

The project includes a local browser interface that accepts rendered RFC plaintext and applies the saved engineered-feature plus TF--IDF logistic-regression model at its saved threshold only to clauses the evidence-first parser classifies as normative, based on explicit uppercase BCP~14 requirement keywords and its quotation, reference, and terminology exclusions. Lowercase-modal and section-context candidates are not scored or presented for human normativity confirmation. The interface displays and exports only positive ambiguity predictions, and optional local Qwen explanations are restricted to those results. Uploaded document text remains local and is not sent to a remote service. Consequences of this conservative gate are discussed in Section~\ref{sec:limitations} (L8).

\subsection{Consecutive-revision alignment}

For revisions $t-1$ and $t$, bidirectional retrieval first searches corresponding and nearby sections, followed by a bounded global fallback. Candidate score $s(i,j)$ combines semantic, lexical, structural, positional, block-type, and protected-token evidence:
\begin{equation}
s(i,j)=\sum_{k} w_k s_k(i,j),
\end{equation}
where semantic and lexical similarity each receive weight 0.38 in the semantic pilot, structure 0.12, and position, block compatibility, and protected-token evidence 0.04 each. Distinctive exact anchors are locked only when supported by section structure. One-to-one components use bipartite assignment with unmatched choices. Competing split and merge candidates of at most three adjacent clauses use a mixed-integer program with non-overlap constraints. Moves require section correspondence or reliable anchor inversions; close alternatives remain \textsc{Uncertain}.

MiniLM embeddings are computed from direct tokenizer-ID windows, avoiding text reconstruction between tokenization stages. The TLS coverage pilot aligns 30 documents across 29 consecutive pairs: 52,137 clause-version occurrences produce 52,953 relationships, including 4,452 modified, 2,356 inserted, 2,025 deleted, 261 split, 260 merged, 1,808 moved, and 5,199 uncertain relationships. Figure~\ref{fig:alignment-counts} visualizes these counts. They establish pipeline coverage, not alignment accuracy: the stratified 150-link review sample has not been adjudicated, so link precision and recall are intentionally unreported. Revision links are not model features in the transformer experiment reported below.

\subsection{Temporal and leakage controls}

For a clause in revision $t$, revision features may depend only on revisions $\leq t$. Later drafts, RFC text, later errata, undated evidence, annotation metadata, and model votes are rejected by a feature guard. RFC endpoints are available for offline correspondence research but not for draft-stage prediction. Family grouping blocks related clauses from crossing train and evaluation roles. Exact normalized cross-partition target overlap is zero in the current artifact. Fitting-side exclusions additionally cover near duplicates, shared lineages, BCP~14 skeleton conflicts, and target-as-context reproduction.

\section{Reference Labels and Partitions}

\subsection{Operational annotation reference}

Candidate clauses were assembled from eleven draft-family review sets after lineage deduplication. Three local models (Gemma~3~27B, GPT-OSS~20B, and Qwen3~32B) independently supplied binary or uncertain decisions. Two agreeing valid votes form the consensus; unanimous consensus is marked high-confidence and a two-of-three decision medium-confidence. Rows without a strict two-vote majority remain uncertain rather than being forced into the negative class. The training export excludes uncertain candidates, rationales, later-revision evidence, and errata-derived features.

The latest matched classical/heuristic comparison uses all 2,425 resolved rows in \texttt{final\_annotation\_ready.csv}: 160 positive (6.60\%) and 2,265 negative clauses across eleven families. This rerun includes TCP and DNS and therefore supersedes the earlier 2,406-row classical result still described in the revision-feature summary markdown; that summary is stale relative to the current metrics manifests. Earlier Qwen/hybrid studies were run on the frozen annotation-ready snapshot, which held 2,424 rows before \texttt{item\_id=2161} was resolved, and are reported here on the same 2,425-row, 160-positive cohort. The updated \texttt{final\_annotation\_ready.csv} includes resolution of the previously unresolved \texttt{item\_id=2161}. Its transformer development cohort contains 2,425 rows (160 positives) across eleven families. The DeBERTa follow-up compares focal loss, partial fine-tuning, and their rank ensemble on the same cohort; the reported analysis repair reuses the parent experiment's validated predictions and does not create independent evaluation evidence. The labels are an operational reference, not independently double-annotated expert gold (L1).

\subsection{Annotation disagreement audit}

The annotation reference is noisy and model-dependent. In the earlier 2,546-row consensus snapshot, 435 of 455 positive rows (95.6\%) had a 2--1 vote split; only 20 were unanimous positive. Among negative rows, 1,325 of 2,091 (63.4\%) had a 2--1 split. This corresponds to an implied weighted positive share of 14.3\%, compared with 17.9\% unweighted. A later leave-one-model-out audit on vote-eligible subsets measured pairwise Cohen's $\kappa$ of 0.113 (Gemma/GPT-OSS), 0.017 (Gemma/Qwen3), and 0.046 (GPT-OSS/Qwen3), despite raw agreement ranging from 0.370 to 0.792. Agreement-conditioned tiers were structurally extreme: the unanimous tier had perfect leave-one-out AP by construction, whereas the medium tier was highly imbalanced and often too small or single-class for stable estimates. The held-out-model vote APs were 0.0157 for Gemma, 0.1047 for GPT-OSS, and 0.3825 for Qwen3 on their respective eligible subsets. Separately, the consensus-trained predictor's AP changed from 0.275 when scored against consensus to 0.737 against Gemma labels, 0.299 against GPT-OSS labels, and 0.028 against Qwen labels on the associated diagnostic snapshot. This target-sensitivity analysis is not a ranking of annotator quality; it shows that scores depend strongly on which model's decisions define the target, and that the consensus target itself is uncertain. A proposed vote-weighted model was not run because the pre-established stop rule triggered when most rows in both classes had weight 0.5.

\section{Models and Experimental Protocol}

\subsection{Evaluation measures}

For scores $p_i$ and labels $y_i$, the primary ranking metric is average precision (AP), computed as the stepwise precision-weighted increase in recall. Repository reports historically call this ``PR-AUC''; here we use the more precise name AP. The no-skill reference is the positive prevalence of the cohort being evaluated: 0.0660 (160/2,425) for the classical and Qwen/hybrid cohorts, and 0.0644 (138/2,143) for the reviewed-label transformer cohort. We also report ROC-AUC, precision, recall, $F_1$, $F_2$, balanced accuracy, confusion counts, and retrieval at fixed review budgets. Threshold-free rankings are primary because the appropriate operating point depends on reviewer capacity and the relative cost of missed ambiguity.

Uncertainty for the transformer study is estimated with 2,000 bootstrap resamples of the nine RFC families. These intervals represent sampling variation across the observed families.

\subsection{DeBERTa variants and rank ensemble}

Inputs contain only the target clause, with a maximum length of 256 tokens and deterministic head--tail truncation; the experiment reports no target truncation. Both models use five epochs, AdamW, learning rate $10^{-5}$, weight decay 0.01, a linear schedule with 10\% warmup, batch size 8, FP32, deterministic execution, and seed 2718. The focal model uses $\gamma=2$ and fitting-side class weights ($\alpha_0=1$, $\alpha_1=N_{-}/N_{+}$):
\begin{equation}
\mathcal{L}_{\mathrm{focal}}=-\alpha_y(1-p_y)^\gamma\log p_y.
\end{equation}
The partial model uses weighted cross-entropy and trains only layers 8--11, the pooler, and classifier.

For the ensemble, each method's empirical cumulative distribution function is fit on the corresponding fitting-side inner OOF scores. The two percentile ranks are averaged with equal weight and applied to the untouched outer-fold predictions. The resulting value is a ranking score, not a calibrated probability.

\subsection{Classical machine learning and heuristic}

The latest classical/heuristic comparison uses 2,425 rows, with 160 positives (6.60\%) from 11 draft families. Models are evaluated using three-fold stratified group cross-validation, keeping draft-family groups intact; feature scaling, TF--IDF vocabulary, and feature selection are fitted within each training fold. The logistic-regression model uses 25 engineered clause features concatenated with word unigram/bigram TF--IDF, class-balanced L1 regularization, and $C=0.5$. The complete recorded model grid also evaluates logistic regression, Linear SVM, and random forest with TF--IDF, frozen 384-dimensional MiniLM embeddings, TF--IDF plus embeddings, engineered-plus-TF--IDF inputs, and engineered-plus-TF--IDF with twelve label-free revision features. These revision features summarize the two preceding draft transitions (the target's $t-1\!\to t$ change and, where available, the predecessor's $t-2\!\to t-1$ change); matching is constrained to drafts available no later than the target revision. The full results are in Table~\ref{tab:classical}. This all-family run includes TCP and DNS, so it is grouped OOF development evidence rather than the untouched reserved-family evaluation proposed originally.

The fixed heuristic is not trained on labels. It assigns hand-set points to conditional clauses lacking exception markers, deictic expressions, mixed BCP~14 modal levels, subjective terms, and exceptions; numeric bounds and explicit target references subtract points. The score is clipped to $[0,9]$, normalized by nine, and thresholded at 0.5. Its rules and threshold are fixed rather than fit per fold. We report average precision from OOF scores and threshold metrics at the recorded operating threshold; the heuristic is a transparent low-cost baseline, not a learned classifier.

\subsection{Earlier family-held-out classical study}

The repository also contains a distinct earlier study with a nine-family leave-one-family-out protocol, 2,540 evaluated clauses, and 17.8\% positive prevalence (453/2,540). Its combined target TF--IDF/engineered baseline (E0) has pooled OOF AP 0.291 (95\% bootstrap interval 0.260--0.335). Frozen MiniLM and BGE-small representations with engineered features reach AP 0.246 and 0.245, respectively. Simple one-revision predecessor signals yield AP 0.168 and 0.165. These results provide historical methodology context only; their cohort and labels differ from the latest 2,425-row ML/heuristic comparison and from the transformer/LM cohorts.

\subsection{Language-model and hybrid study}

We also report the repository's separate Qwen3-32B development study~\cite{yang2025qwen3}, which uses the frozen \texttt{final\_annotation\_ready.csv} label artifact: 2,425 clauses, including 160 positives (6.60\%). It uses the five family-grouped outer folds defined for that artifact and is evaluated separately from the 2,143-clause, 138-positive reviewed-label DeBERTa study. The model is a local quantized Qwen3 32B inference model; V1 and V2 update no model parameters. V1 compares zero-, four-, and eight-shot prompts, selecting demonstrations from fitting families and scoring the \texttt{yes}/\texttt{no} alternatives from native token log-probabilities. V2 tests stricter prompts with 8, 16, or 24 fold-safe demonstrations, including prevalence-aware class proportions, and estimates threshold operating points by cross-fitting. V3 combines frozen Qwen zero-shot scores with a nested, target-only word/character TF--IDF logistic classifier; its regularization and blend weight are chosen using inner-fold predictions. V4 combines the V3 score with frozen MiniLM semantic representations of the target and local context using the Sentence-BERT bi-encoder paradigm~\cite{reimers2019sbert}. The semantic classifiers use class-balanced logistic regression ($C=0.03$); the 0.80/0.10/0.10 V3/target/context combination was selected on development data. V3 and V4 are supervised hybrid models, not parameter-fine-tuned LLMs. Results are reported in Section~\ref{sec:llm-results}.

\subsection{Nested operating points}

Threshold selection is performed only on the fitting side. For each outer fold, three family-disjoint inner folds estimate method-specific thresholds. The policy maximizes recall subject to minimum fitting precision in $\{0.20,0.30,0.50\}$, breaking ties by higher precision and then higher threshold. Infeasible targets remain missing; they are not replaced by an always-positive rule. Precision targets are objectives on inner data, not guarantees on a held-out family.

\section{Revision-Feature Implementation}

The current classical experiment adds twelve compact numerical features to the engineered-plus-TF--IDF representation. H0 describes the immediate $t-1\!\rightarrow t$ transition and H1 describes $t-2\!\rightarrow t-1$ after following the H0 predecessor. Each tier includes predecessor availability; unchanged, modified, and moved indicators; and match-based and lexical change distances. The feature loader reads only \texttt{item\_id}, \texttt{record\_id}, and \texttt{family\_id} from the annotation identity key. It rejects duplicate identities, unexpected matcher versions, and document mismatches. Labels, candidate-source fields, votes, rationales, future drafts, final-RFC endpoints, and errata are excluded. Numerical scaling is fit separately on each training fold, and every final manifest records the feature schema plus hashes of all matcher caches.

\section{Model and Artifact Interfaces}

The classical runners share one feature-construction interface so that logistic regression, Linear SVM, and random forest receive identically ordered inputs. Every experiment writes fold metrics, OOF scores, a metrics summary, a provenance manifest, raw revision features when used, and a final development model. Plot generation discovers saved metrics, checks cohort compatibility, and compares only runs with the same row count, positive count, and fold composition. The report uses the OOF artifacts for evaluation; final models fit on all development rows are retained only for downstream prototype use.

\section{Local Review Prototype}

The local interface is a human-in-the-loop inspection tool. It parses a selected RFC, applies the saved classical model to eligible BCP~14 clauses, and presents ranked clauses with surrounding text and filtering controls. Optional local-Qwen explanations are requested only for selected results and do not alter the classifier score. This separation prevents generated explanations from silently becoming prediction features. The interface does not implement an autonomous publication gate.

\section{Implementation Choices and Reproducibility}

Python, pandas, SciPy, scikit-learn, PyTorch, Hugging Face Transformers, and sentence-transformers provide the main implementation stack. Fixed seeds, immutable input manifests, SHA-256 hashes, family-level fold assignments, and serialized preprocessing objects support repeatability. Cached local-model outputs reduce nondeterministic or costly reruns. Artifact availability is described in Section~\ref{sec:limitations} (L7).

\subsection{Operating-point utility and error analysis}

The examples below are held-out outer-fold predictions at the same nested 0.50 fitting-precision target reported in Table~\ref{tab:ranking}. Scores are ensemble ECDF ranks, not probabilities; the listed threshold is the fold-specific threshold. The reference label is the project's operational annotation, not independent expert gold. Each interpretation is a plausible reading of the example, not a causal explanation established by the experiment.

\begin{itemize}[leftmargin=*]
  \item \textbf{True positive --- draft-ietf-quic-http-24, Section 11.3, ``Settings Parameters.''} The preceding definition says ``Default: The value of the setting unless otherwise indicated''; the target says ``SHOULD be the most restrictive possible value.'' Reference: Yes; prediction: Yes (score 1.000, threshold 0.900). The subjective phrase ``most restrictive possible'' is a plausible local cue for underspecification.
  \item \textbf{True positive --- draft-ietf-quic-tls-22, ``Peer Denial of Service.''} After describing how disproportionate processing can exhaust resources, the target says implementations ``SHOULD track redundant packets and treat excessive volumes of any non-productive packets as indicative of an attack.'' Reference: Yes; prediction: Yes (score 1.000, threshold 0.902). Terms such as ``excessive'' and ``non-productive'' leave room for interpretation, which may have helped the target-only model rank it highly.
  \item \textbf{False positive --- draft-ietf-quic-transport-34, Section 17.1, ``Packet Number Encoding and Decoding.''} The target says ``An endpoint SHOULD use a large enough packet number encoding to allow the packet number to be recovered even if the packet arrives after packets that are sent afterwards.'' The next clause gives a lower bound using the base-2 logarithm of contiguous unacknowledged packet numbers. Reference: No; prediction: Yes (score 0.999, threshold 0.922). A plausible explanation is that the model sees the target without the adjacent clause that makes the recommendation concrete.
  \item \textbf{False positive --- draft-ietf-httpbis-http2bis-07, ``GOAWAY.''} The target says ``Endpoints SHOULD always send a GOAWAY frame before closing a connection so that the remote peer can know whether a stream has been partially processed or not.'' The following text illustrates the case. Reference: No; prediction: Yes (score 0.976, threshold 0.900). A possible source of the false alarm is sensitivity to prescriptive wording despite the explanatory context; this mechanism was not separately tested.
  \item \textbf{False negative --- draft-ietf-quic-tls-34, Section 6.5, ``Receiving with Different Keys.''} The preceding clause describes a period after promoting new receive keys; the target says ``These updated keys MAY replace the previous keys at that time,'' followed by a caveat that peers may have different RTT views. Reference: Yes; prediction: No (score 0.116, threshold 0.902). The temporal reference and key-state relationship may require context or protocol reasoning not expressed as a strong local lexical cue.
  \item \textbf{False negative --- draft-ietf-httpbis-http2bis-07, ``Stream Identifiers.''} After a clause about streams opened using HEADERS and reserved using PUSH\_PROMISE, the target says ``An endpoint that receives an unexpected stream identifier MUST respond with a connection error of type PROTOCOL\_ERROR.'' The next clause describes a HEADERS-frame transition. Reference: Yes; prediction: No (score 0.204, threshold 0.900). This case has explicit normative language but its possible ambiguity depends on protocol-state interpretation; the target-only input may not expose that issue. The explanation is tentative.
\end{itemize}

The examples show that local lexical cues can support correct rankings, while neighboring clauses can resolve apparent vagueness and some reference-positive cases require technical context. They are illustrative cases selected from the errors, not a representative estimate of error causes.

\section{Conditional ML-to-LLM Routing}
\label{sec:routing-results}

To investigate RQ4, we evaluated a fixed uncertainty-band router using stored out-of-fold (OOF) ML and V4 scores. The aligned routing cohort contains 2,096 clauses and 109 positives. It was formed by matching the available prediction records and excluding 46 rows with conflicting labels; no ML prediction rows were missing. This routing analysis therefore uses an aligned subset of prediction artifacts and is not the full 2,143-clause DeBERTa cohort used in Table~\ref{tab:ranking}. Results below are specific to this aligned cohort and are not a replacement for or direct comparison with the other model results in this chapter.

With ML score $p_{\mathrm{ML}}$, the primary policy sends clauses with $0.4 \leq p_{\mathrm{ML}} < 0.7$ to the LLM; clauses below 0.4 are classified negative by ML, and clauses at or above 0.7 are classified positive by ML. Routed clauses use the V4 score with a 0.5 decision threshold. The ranking score orders ML-negative, routed, and ML-positive tiers, with within-tier percentiles from the model that supplied the decision. For this analysis, LLM decisions are simulated using cached V4 probabilities: no live LLM inference calls were made. Thus, call counts are estimated invocations under the routing policy, not observed production calls.

\chapter{Discussion}

\section{Answers to the Proposal Research Questions}

\subsection{RQ1: Draft-Stage Detection Effectiveness}

The experiments show that contemporaneous draft text contains useful ranking signal against the project's operational reference. On the matched classical cohort, engineered features plus TF--IDF reach AP 0.3584 with a Linear SVM at 6.60\% prevalence. On the nine-family, 2,143-clause reviewed-label transformer cohort (138 positives; 6.44\% prevalence), the DeBERTa rank ensemble reaches AP 0.6736 and retrieves 19 of 20 reference positives in its pooled top-20 ranking. These estimates use only information available at the evaluated draft revision and isolate draft families across folds. RQ1 is therefore answered as a development-stage feasibility result, not as validated prospective accuracy (Section~\ref{sec:limitations}).

\subsection{RQ2: Revision History, Cross-References, and Calibration}

The controlled classical ablation does not support a consistent revision-feature improvement. Revision features change AP by $-0.0081$, $-0.0012$, and $-0.0015$ for logistic regression, SVM, and random forest; corresponding $F_2$ changes are $0.0000$, $+0.0110$, and $+0.0227$. Earlier predecessor-only models also remained near or below their cohort prevalence. These are observed outcomes; plausible but untested explanations include a weak or indirect relationship between revision changes and ambiguity, noise in clause matching, or redundancy with lexical and engineered features. The mixed $F_2$ changes also show that thresholded behavior can differ from ranking behavior. Cross-reference counts are included among engineered features, but no isolated cross-reference ablation was completed, and no Brier score, expected calibration error, or calibration curve was recorded (L6). RQ2 is therefore partly answered, and hypothesis H1 is not supported as a general claim.

\subsection{RQ3: Comparison of Model Families}

Table~\ref{tab:rq3-comparison} summarizes the evidence without presenting incompatible cohorts as a common leaderboard. Fine-tuned DeBERTa provides the strongest observed ranking result in its own cohort. Classical engineered-plus-TF--IDF models provide competitive, inexpensive, and auditable rankings in their cohort. Direct Qwen prompting provides high recall but low precision, and its fitted lexical--semantic hybrid improves ranking within the Qwen study. The heuristic is most transparent but substantially weaker. These results support different practical roles rather than a universal model winner: a classical model is a reasonable choice when CPU-only inference, feature-level auditability, or simpler deployment is prioritized; a transformer is a candidate when ranking quality and top-budget retrieval are the priority and inference resources are available. The cross-cohort results do not establish this trade-off in a controlled head-to-head comparison. Reproducibility is strongest for deterministic rules and classical pipelines and weaker for hardware-dependent local-LLM runs. A common latency, energy, token-cost, or monetary-cost benchmark was not recorded. RQ3 is therefore answered for effectiveness and workload only under separate protocols (L5).

\subsection{RQ4: Hybrid Routing and LLM-Call Reduction}

The fixed-band router in Section~\ref{sec:routing-results} sends uncertain ML cases to the LLM and estimates 79.0\% fewer calls than LLM-only on its 2,096-row aligned OOF cohort. Hybrid AP is 0.330 versus 0.372 for LLM-only, while $F_2$ is 0.457 versus 0.447. Paired family-bootstrap intervals for AP, $F_2$, and recall at a 20\% review budget all include zero. Thus, the experiment finds no statistically detectable difference on these measures, but it does not establish equivalence or formal non-inferiority; moreover, cached V4 scores simulate the LLM and no live calls were made. RQ4 is partly answered: the routing policy demonstrates an estimated call-reduction mechanism with comparable observed thresholded performance on this development subset, while effectiveness preservation and actual cost savings require a prospective, live-inference evaluation. Hypothesis H2 receives preliminary, not confirmatory, support.

\subsection{RQ5: Evidence and Explanation Quality}

The local application can request optional Qwen explanations for selected clauses, and the prompting formats can emit rationales or structured fields. However, the repository contains no completed expert study of evidence-span correctness, ambiguity-subtype accuracy, rationale--label agreement, hallucinated-reference rate, usefulness, or clarity. Explanation text is not used as a prediction feature and is presented as a hypothesis to reviewers. RQ5 and hypothesis H3 therefore remain unanswered; classifier effectiveness cannot be used as a proxy for explanation faithfulness.

\section{Interpretation of the Development Results}

\emph{Ranking signal.} Among the three methods evaluated on the same transformer cohort, the rank ensemble has the highest observed AP and top-budget retrieval, but its family-cluster interval overlaps those of focal loss and partial fine-tuning; the ordering is descriptive, not a significance result. At the nested 0.50 fitting-precision target, it flags 149 clauses, including 87 reference positives, while missing 51 of 138 positives. This is a review-prioritization result, not an automatic decision rule. In the separate language-model study, direct Qwen prompting gives high recall at low precision in V1, the stricter V2 prompt substantially reduces recall and AP, and adding a nested lexical classifier (V3) and frozen semantic features (V4) improves AP within that study's development cohort. These results neither establish that LLMs outperform DeBERTa nor permit numeric comparison across cohorts (L5).

\emph{Family heterogeneity.} In the transformer OOF cohort, ensemble AP ranges from 0.571 to 0.796 across families with at least 150 clauses and positive labels. Smaller families are especially unstable: AP is 1.000 for a five-clause family with two positives and 0.917 for a 54-clause family with three positives; a one-clause family has no positives, so AP is undefined. The data establish variation in observed family scores, not its cause. Differences in sample size, prevalence, terminology, or ambiguity patterns are plausible contributors, but this study cannot distinguish them; family-specific conclusions are consequently weak for the smallest groups.

\emph{Classical and revision evidence.} On the classical/heuristic cohort, engineered features combined with TF--IDF produced stronger AP than the fixed heuristic and the tested embeddings-only baselines, supporting the value of lexical and explicit clause cues for ranking. The high-recall logistic operating point has low precision and does not remove the need for human review. The twelve revision features change AP only slightly, and by different signs for $F_2$; frozen embeddings and basic predecessor features did not improve the matched LOFO baseline in the recorded setup, which is not evidence that semantic or temporal context is universally unhelpful. Weak or noisy revision correspondence and feature redundancy are hypotheses, not findings. The fixed three-component rank ensemble reaches AP 0.4619 on the label-compatible 2,097-row intersection; its narrow AP difference over the classical component is descriptive, not evidence of complementary generalization.

\emph{Revision alignment.} Revision alignment provides useful lineage and leakage-control infrastructure, but its pilot has not been evaluated against adjudicated gold links and its outputs are not used as predictive features in the transformer study.

\emph{Use in review.} Ranking is more defensible than a binary gate. The inner-fold thresholds optimize a precision constraint on fitting data, but pooled OOF behavior and family-specific outcomes show that the constraint does not transfer uniformly. A user-facing system should present clauses for expert review, expose source revision and surrounding context, and avoid claims that a low score certifies correctness.

\section{Deployment Interpretation}

The local review prototype applies the saved engineered-feature/TF--IDF logistic model only to clauses classified as normative by explicit uppercase BCP~14 keywords after parser exclusions. The transformer ensemble is a research candidate and is not wired for live single-RFC scoring. Optional local Qwen explanations are restricted to flagged results and do not affect predictions. The prototype is not an evaluated deployment system (L8), and automatic rejection or publication certification is inappropriate. The top-budget results in Table~\ref{tab:reviewed-topk} are retrospective diagnostics, not estimates of production precision or reviewer yield.

\section{Reproducibility and Governance}

The experiment records hashes for the authoritative label source, effective dataset, model snapshot, folds, configuration, and derived predictions. The reviewed-label source/effective-dataset SHA-256 values begin \texttt{8ffa654c2c40} and \texttt{4e20a2571bfe}. Full hashes remain in the experiment manifests. The model snapshot is used offline, and the experiment manifest pins seed, tokenizer, and training configuration. The analysis-repair version validates and reuses the parent experiment's 40 prediction artifacts; it does not retrain models or constitute a second evaluation. Code and selected aggregate tables are available in the project repository~\cite{artifact2026}; artifact availability is discussed in L7.

\section{Limitations}
\label{sec:limitations}

All limitations of the study are consolidated here; other sections refer to them by label (L1--L9). They bound every result in this report.

\begin{itemize}[leftmargin=*]
  \item \textbf{L1. Annotation reference.} Labels operationalize ambiguity through a particular rubric and a three-model workflow (Gemma, GPT-OSS, Qwen3) with manual conflict verdicts. They are not blinded, independent, double expert annotation and do not exhaust RFCScope's seven subtypes. Pairwise $\kappa$ was low, a large share of positive votes were two-to-one, and scores shift strongly under alternative model targets. Qwen3 contributed to annotation support, so the Qwen agreement analysis is not independent of label construction. No experiment estimates human inter-annotator reliability against adjudicated expert gold.
  \item \textbf{L2. Candidate selection and provenance counts.} Candidates are enriched, not population-random, so AP and prevalence do not transport to all Internet-Draft clauses. The evaluated LOFO artifact contains five errata-derived rows (all negative, all TLS), whereas an earlier progress report cited 121 errata positives and 242 TLS records. The 31 verified errata count refers to source documents, not positive clause labels; until the row-level definition is reconciled, errata-derived results are not a comprehensive errata evaluation.
  \item \textbf{L3. Validation scope.} Family splits, fitting-only preprocessing, inner-only thresholds, and duplicate/lineage exclusions reduce leakage but cannot remove pretraining contamination from public RFCs. Nine families contribute to the reviewed-label study, with QUIC/HTTP dominating. TCP and DNS were consumed by the all-family reruns, so they are not untouched tests. Routing protocols outside the cohort, other standards bodies, and newly authored drafts are untested, and no temporal or independent external test exists.
  \item \textbf{L4. Statistical scope.} Family bootstrap intervals over nine transformer-cohort clusters are wide, and overlapping intervals preclude a superiority claim. Architecture, feature, and hybrid (V3/V4) choices were made adaptively during development, so results are development evidence, not a pre-registered benchmark. Pooled metrics weight records, and the smallest families cannot support stable standalone estimates.
  \item \textbf{L5. Comparability.} Classical, Qwen/hybrid, and transformer results use different label snapshots, cohorts, folds, and protocols and form no unified leaderboard.
  \item \textbf{L6. Revision evidence.} The revision ablation tests twelve features from a simplified one-to-one predecessor matcher without split/merge handling. The full TLS alignment has no adjudicated gold links, and its confidence is rule-based and uncalibrated. No isolated cross-reference ablation or calibration measure (Brier score, expected calibration error, reliability diagram) was completed, so the negative result cannot locate its cause in signal, representation, or matching quality.
  \item \textbf{L7. Artifacts and reproduction.} Private annotation exports, row-level outputs, model weights, and large run directories are intentionally absent from the released repository, so a fresh clone cannot reproduce every table, and the result tables alone are insufficient for full independent reproduction.
  \item \textbf{L8. Prototype and end-to-end validity.} The prototype scores only clauses passing the uppercase BCP~14 gate and so may omit genuine normative clauses; scores are not calibrated probabilities and the saved threshold is not deployment-validated. Explanation quality was not evaluated. Parsing can lose context, a displayed explanation can mislead, and a user can overinterpret a low score; none of these is represented by AP on a frozen clause table.
  \item \textbf{L9. Hybrid-routing evidence.} The routing comparison uses 2,096 aligned OOF records after excluding 46 label conflicts, rather than all 2,143 records in the reviewed-label transformer cohort. V4 responses are simulated from cached probabilities, so the reported 79.0\% call reduction is an estimated routing rate, not a measured reduction in live inference calls, latency, or cost. The paired family-bootstrap intervals include zero but are wide; without a prespecified non-inferiority margin, they do not show that effectiveness is preserved. Models and bands were developed on project data, so the analysis is exploratory rather than an independent test.
\end{itemize}

\section{Ethical and Practical Considerations}

All source standards and errata are public technical documents. The principal risk is epistemic rather than personal: an incorrect ``ambiguous'' flag could waste reviewer time or unfairly characterize an author's work, while a false negative could create unwarranted confidence. The system must expose uncertainty, provenance, and its non-certification role. Generated explanations should be treated as hypotheses and checked against the exact contemporaneous text. Final evaluation should be reported once, including negative outcomes, and the sealed set should not be recycled for iterative tuning.

\chapter{Conclusion and Future Work}

\section{Summary of Achievements}

\system{} combines corpus acquisition, structural parsing, normative-clause segmentation, revision alignment, lineage-aware candidate construction, AI-assisted consensus annotation, and grouped classical/transformer/LLM evaluation. The project reports correspondence coverage separately from ambiguity classification and excludes later revisions, RFC endpoints, errata, annotation votes, and rationales from model features. In the reviewed-label transformer study, focal loss, partial fine-tuning, and their equal-weight fitting-side ECDF ensemble were evaluated on the same 2,143-clause, nine-family cohort (138 positives; 6.44\%): AP was 0.5823, 0.5761, and 0.6736, respectively. Other studies reported AP 0.3584 for the all-family classical SVM, 0.291 for TF--IDF-plus-engineered features in an earlier nine-family LOFO study, and 0.1960 for eight-shot Qwen and 0.3252 for its V4 lexical/semantic hybrid. A supplemental conditional-routing analysis on 2,096 aligned OOF records estimates 79.0\% fewer LLM calls than LLM-only, with AP/F$_2$ 0.330/0.457 versus 0.372/0.447; cached LLM scores were used, and confidence intervals do not establish non-inferiority. These cross-study values are not a unified leaderboard. The local review GUI runs the saved classical logistic-regression artifact; the transformer ensemble is a research candidate. The attempted second-generation annotation panel produced no corpus labels because it was blocked at preflight.

The strongest conclusions are methodological rather than deployment claims: family-isolated evaluation is feasible; target text and transparent lexical/engineered features provide useful ranking signal against the operational reference; the tested revision features do not improve ranking AP in the latest matched rerun; and performance depends on model family, data snapshot, evaluation protocol, and annotation target. The limitations in Section~\ref{sec:limitations} prevent a claim of validated ambiguity-detection accuracy.

\section{Future Work}

Before making a deployment or final-generalization claim, the project should: (1) independently double-annotate and adjudicate a stratified expert sample; (2) evaluate the conditional router with live LLM inference on a label-consistent cohort, record actual calls, latency, energy or token use, and monetary cost, and prespecify a non-inferiority margin against an LLM-only baseline; (3) isolate cross-reference features and add Brier score, expected calibration error, and reliability diagrams; (4) conduct blinded expert assessment of evidence spans, subtype assignments, rationale faithfulness, hallucinated references, usefulness, and clarity; (5) validate revision links, including split/merge relationships, against a reviewed alignment sample; and (6) preregister and preserve a new genuinely untouched evaluation, such as unseen draft families or later time-sliced revisions, because TCP and DNS have already entered the classical evaluation. Until those steps are complete, the appropriate claim is a reproducible, promising development-stage review aid---not a published-standard oracle or autonomous quality gate.

\chapter{Reproduction and User Instructions}

\section{Revision-Augmented Classical Experiments}

Run the following commands from the repository root. They reproduce the current revision-augmented classical runs and comparison plots when the tracked annotation and matcher-cache inputs are present.

\begin{verbatim}
python -m models.classical.train_annotation_engineered_tfidf_revision
python -m models.classical.annotation_classifier_experiments \
  --classifier linear_svm --feature-mode engineered_tfidf_revision
python -m models.classical.annotation_classifier_experiments \
  --classifier random_forest --feature-mode engineered_tfidf_revision
python -m models.classical.plot_annotation_results
python paper/generate_report_figures.py
\end{verbatim}

The principal outputs are stored in:
\begin{itemize}[nosep]
    \item \path{results/ML/v2_engineered_tfidf_revision/};
    \item \path{results/ML/additional_classifiers/}; and
    \item \path{results/ML/figures/}.
\end{itemize}
Each revision run includes OOF predictions, fold metrics, raw revision features, a final development model, and a provenance manifest.

\section{Hybrid Routing Analysis}

The supplementary conditional-routing analysis is implemented in \texttt{models/hybrid/routing\_vs\_llm\_only.py}. It consumes stored OOF ML and V4 prediction files and writes aggregate outputs to \texttt{results/hybrid/routing\_vs\_llm\_only/}. The analysis simulates LLM decisions from cached V4 probabilities and does not issue inference calls. The script refuses to overwrite an existing output directory.

\section{Local Review Application}

After restoring the approved classical model artifact described in the repository README, start the local application with:

\begin{verbatim}
python -m gui.app
\end{verbatim}

The interface binds to \texttt{http://127.0.0.1:8765/}. A reviewer can upload a rendered RFC text file, inspect positive-ranked clauses, filter by section, download results, and optionally request local explanations for at most five selected clauses. Scores are not calibrated probabilities and results require human verification.

\section{Report Build and Validation}

Generate the report-specific figures first, then compile the bibliography and report from the \texttt{paper/} directory:

\begin{verbatim}
python paper/generate_report_figures.py
cd paper
pdflatex main
bibtex main
pdflatex main
pdflatex main
\end{verbatim}

Focused regression tests for the revision features, classical runners, and result plotting are:

\begin{verbatim}
python -m pytest -q tests/test_revision_features.py \
  tests/test_annotation_logreg_experiment2.py \
  tests/test_annotation_classifier_experiments.py \
  tests/test_plot_annotation_results.py
\end{verbatim}

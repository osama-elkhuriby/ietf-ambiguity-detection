\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
Natural-language protocol specifications can permit multiple plausible implementations even when they use the normative keywords of BCP~14. Detecting such ambiguity before an Internet-Draft becomes an RFC is difficult because clauses recur across revisions, positive cases are rare, and final RFC or erratum evidence can leak into draft-stage prediction. This report presents \system{}, a revision-aware corpus, annotation workflow, modeling pipeline, and local review prototype designed around temporal information boundaries and draft-family-isolated evaluation. The corpus contains 253 draft revisions, 12 RFCs, and 31 verified technical errata. Separate development studies evaluate a deterministic heuristic, classical machine learning, frozen embeddings, contemporaneous revision features, Qwen3 prompting and lexical--semantic hybrids, and DeBERTa variants. On the latest 2,425-row matched classical cohort (160 positives), engineered features plus TF--IDF obtained AP 0.3584 with a Linear SVM, 0.3363 with a random forest, and 0.3265 with logistic regression. Adding twelve past-only revision features changed these values to 0.3572, 0.3348, and 0.3185, respectively, so revision history did not improve ranking AP in this rerun. On the separate 2,143-clause reviewed-label transformer development cohort, a fitting-side ECDF ensemble of two DeBERTa variants obtained AP 0.6736, compared with 0.5823 and 0.5761 for its components. These confidence intervals overlap, only one seed was run, and 100 human-confirmed records were selected from historical errors; the result is descriptive rather than an independent generalization estimate. A separate Qwen/MiniLM hybrid reached AP 0.3252, but the intended conditional LLM-routing, standardized latency/cost comparison, and expert evaluation of explanation faithfulness were not completed. Moreover, the latest classical rerun includes the TCP and DNS families that the proposal intended to reserve, so they can no longer serve as untouched project-level holdouts. The project therefore answers the proposal's effectiveness and revision-ablation questions with qualified development evidence, while the LLM-call-reduction and explanation-quality questions remain open. \system{} should be treated as a human-review prioritization aid, not an autonomous ambiguity judge.

\noindent\textbf{Keywords:} Internet-Drafts, RFC, ambiguity detection, protocol specifications, natural language processing, DeBERTa, document evolution, leakage control.

\chapter{Introduction}

\section{Background and Problem Statement}

The Internet Engineering Task Force (IETF) develops protocols through sequences of mutable Internet-Drafts before stable RFC publication. Although capitalized terms such as \emph{MUST}, \emph{SHOULD}, and \emph{MAY} have defined meanings under BCP~14~\cite{rfc2119,rfc8174}, their surrounding prose can still leave actors, conditions, references, failure behavior, or interactions under-specified. Multiple standards-conforming interpretations can then produce interoperability defects or security-relevant implementation differences.

Prior systems show that protocol prose can be analyzed automatically. SAGE combines semantic parsing and author clarification to disambiguate RFC text and generate code~\cite{yen2021sage}. NRFCKG represents protocol requirements as a knowledge graph and searches for contradictions~\cite{feng2023nrfckg}. Most directly, RFCScope derives seven logical-ambiguity subtypes from verified errata and uses an LLM pipeline to find ambiguities in published RFCs~\cite{pawagi2025rfcscope}. These systems motivate automated support, but they do not answer a different operational question: \emph{could a risky clause have been prioritized while it was still an Internet-Draft, using only information available at that time?}

\section{Motivation}

That question introduces three hazards. First, a final RFC, later revision, or later erratum is an informative label source but an invalid prediction-time feature. Second, clause-level random splits place nearly identical text from the same revision lineage on both sides of an evaluation. Third, the positive class is rare, so accuracy and even ROC area can obscure poor retrieval of ambiguous clauses; precision--recall analysis is more informative under skew~\cite{davis2006pr,saito2015pr}.

\section{Aim, Objectives, and Research Questions}

This paper reports a complete development-stage study of \system. Its central design principle is separation: source collection, structural parsing, revision alignment, candidate construction, annotation, model input, model selection, reserved validation, and sealed testing are distinct, hash-recorded stages. The intended output is not an automatic declaration that a standard is defective. It is a ranking that helps an author or reviewer allocate attention.

The project evaluates the five research questions defined in the approved proposal:

\begin{enumerate}[label=\textbf{RQ\arabic*:},leftmargin=*]
  \item How effectively can ambiguous requirements be detected in historical Internet-Drafts using only information available at the evaluated draft version?
  \item Do contemporaneous revision-history and cross-reference features improve $F_2$, PR-AUC, and calibration over text-only models?
  \item How do heuristic, classical ML, fine-tuned transformer, LLM-only, and hybrid approaches compare in effectiveness, reproducibility, latency, cost, and review workload?
  \item Can hybrid routing preserve or improve detection effectiveness while reducing LLM calls relative to an LLM-only approach?
  \item How faithful and useful are the evidence spans, ambiguity subtypes, and explanations produced by the LLM verifier?
\end{enumerate}

The proposal also stated four hypotheses: revision-history features would improve $F_2$ and PR-AUC; hybrid routing would retain effectiveness while reducing LLM use; evidence grounding would reduce unsupported explanations; and random clause splitting would be more optimistic than family/temporal splits. This report distinguishes tested, partly tested, and untested claims rather than treating implementation as confirmation.

\section{Scope and Contributions}

The contributions are:

\begin{itemize}
  \item A revision-aware corpus covering 253 draft revisions, 12 RFCs, and 31 verified technical errata, with future-information guards.
  \item A reproducible annotation workflow spanning eleven draft families, with explicit consensus rules, source provenance, and temporal-information controls.
  \item Matched-cohort evaluation of classical classifiers and a deterministic heuristic, plus separate leave-one-family-out comparisons of lexical, engineered, embedding, contextual, and revision-history features.
  \item Separate, auditable studies of local Qwen prompting and lexical/semantic hybrids, transformer weighting and context/soft-label ablations, and a hash-pinned target-only DeBERTa-v3-base comparison.
  \item A project-wide accounting of early low-prevalence pilots, nested calibration and routing experiments, cross-model rank ensembles, protocol corrections, and blocked or incomplete study lines, so null and unavailable evidence is not silently omitted.
  \item Family-isolated OOF, nested threshold, family-robustness, and fixed-review-budget analyses, reported without conflating their distinct data artifacts.
  \item A claim boundary: AI-assisted labels are not adjudicated expert gold, model-vote agreement is limited, the final transformer uses one seed, and the proposal's TCP/DNS holdouts were consumed by the latest all-family classical rerun even though they remain excluded from the transformer and Qwen development studies.
\end{itemize}

The scope is binary clause-level prioritization for human review. It excludes autonomous standards certification, automatic protocol implementation, and claims that the absence of an erratum proves clarity. The completed experiments are development studies over several explicitly separated annotation snapshots. Although the transformer and Qwen studies preserve their nine-family development boundary, the latest classical rerun evaluates all eleven labeled families, including the proposed TCP and DNS holdouts. The repository therefore has no longer an untouched project-level TCP/DNS test, and no independently sampled expert-gold test set was completed.

\chapter{Background and Literature Review}

\section{Ambiguity in Requirements and Protocol Text}

Ambiguity detection in requirements engineering includes lexical/rule-based indicators, supervised classifiers, and contextual language models. TAPHSIR combines machine learning for anaphoric-ambiguity detection with a BERT-based resolution component~\cite{ezzini2022taphsir}; a recent hybrid requirements study combines ambiguous-phrase rules with conventional classifiers~\cite{izhar2025ambiguity}. These systems demonstrate complementary roles for interpretable cues and learned representations. Their metrics are not transferable to Internet-Drafts, however, because ambiguity definitions, annotation units, prevalence, and document-family dependencies differ. In protocol text, a phrase can be lexically vague yet harmless under a surrounding state machine, while a precise-looking clause may still omit an actor, boundary, or conflict-resolution rule.

Protocol specifications add domain structure: packet fields, state transitions, normative strength, cross-references, and compatibility requirements. SAGE converts selected RFC prose to logical forms, asks humans to resolve remaining alternatives, and generates protocol code~\cite{yen2021sage}. PROSPER uses LLMs to extract protocol state machines from RFC text and diagrams~\cite{sharma2024prosper}. NRFCKG targets direct and conditional contradictions using extracted entities, rules, and constraint solving~\cite{feng2023nrfckg}. These systems address important neighboring problems. Formalization and contradiction checking can establish specific logical properties, but they do not by themselves prioritize ordinary draft clauses for human ambiguity review.

RFCScope is the closest conceptual predecessor. It analyzes 273 verified technical errata, defines seven subtypes under inconsistency and under-specification, and uses context construction, semantic partitioning, subtype-aware LLM analysis, and validation. Its evaluation reports 31 new ambiguities in 14 of 20 RFCs, including author-confirmed cases~\cite{pawagi2025rfcscope}. We use its subtype vocabulary as conceptual guidance, not as an automatic label oracle. Our prediction-time unit is a clause in a historical draft revision; our binary operational question is whether an ordinary implementer could reasonably derive materially different implementation behavior from the available text.

\section{Document Evolution and Leakage-Aware Evaluation}

Scientific-writing resources such as arXivEdits and CASIMIR model document change through aligned versions and edit categories~\cite{jiang2022arxivedits,tinnes2024casimir}. Protocol specifications share the need to represent insertions, deletions, moves, splits, and merges, but a change is not itself evidence of ambiguity: revisions also contain editorial cleanup, new functionality, and terminology updates. This distinction motivates measuring alignment coverage separately from label quality and detector performance.

Evaluation must also respect the intended use. If the goal is transfer to a protocol family not seen during fitting, random clause-level splits are optimistic because clauses, templates, and lineages recur. Family-grouped evaluation is therefore more relevant than random splits, although it estimates transfer only over observed families and cannot substitute for a prospective test. Under rare-positive labels, average precision and precision--recall curves are more informative than accuracy alone~\cite{davis2006pr,saito2015pr}. Our contribution relative to prior work is not a new general ambiguity taxonomy; it is an end-to-end draft-stage study that makes temporal availability, family isolation, candidate selection, source-label artifacts, and evaluation cohorts explicit.

\section{Revision Alignment}

Document evolution has been studied outside networking. arXivEdits provides multi-version scientific papers with sentence alignments and edit intentions~\cite{jiang2022arxivedits}; CASIMIR extends revision corpora at larger scale~\cite{tinnes2024casimir}. Those datasets establish that insertion, deletion, movement, split, and merge must be represented explicitly. In a protocol specification, however, a textual change is not itself evidence of ambiguity: it may introduce functionality, update terminology, or merely edit style. We therefore separate \emph{correspondence} from \emph{ambiguity}, and never use the final RFC or future revision as a detector input.

\section{Models for Imbalanced Text Classification}

The reviewed-label experiment compares two target-only \texttt{microsoft/deberta-v3-base} classifiers and an equal-weight rank ensemble on one frozen cohort. DeBERTa-v3 uses replaced-token detection and gradient-disentangled embedding sharing~\cite{he2023debertav3}. Focal loss emphasizes hard examples under class imbalance~\cite{lin2017focal}. The partial model freezes embeddings, the shared backbone, and layers 0--7, and trains layers 8--11, the pooler, and classifier. Earlier local-Qwen/hybrid and classical studies are reported separately because they were evaluated under different data and validation protocols.

\subsection{Collection and structural parsing}

The curated corpus covers application, DNS, routing, security, and transport standards. Twelve RFCs and all available histories for ten modern draft families are stored; OSPFv2 and BGP-4 are RFC-only because their historical drafts are not available through the same archive. The audit reports 253 expected and present draft revisions, 12 expected and present RFCs, and 31 verified technical errata.

The parser accepts both Datatracker plaintext and XML2RFC. It emits a common document--section--block tree while retaining original text, section paths, source locations, reference targets, tables, artwork, and formal syntax. A deterministic clause layer conservatively separates prose and list items. It recognizes uppercase BCP~14 keywords while guarding quoted text, references, abbreviations, version numbers, URLs, and condition--requirement pairs. Each clause receives a stable identifier and one of \textsc{Normative}, \textsc{Contextual}, \textsc{Excluded}, or \textsc{Manual Review}. This stage identifies likely requirements; it does not decide ambiguity.

\subsection{Local RFC-review prototype}

The project includes a local browser interface that accepts rendered RFC plaintext and applies the saved engineered-feature plus TF--IDF logistic-regression model at its saved threshold only to clauses the evidence-first parser classifies as normative, based on explicit uppercase BCP~14 requirement keywords and its quotation, reference, and terminology exclusions. Lowercase-modal and section-context candidates are not scored or presented for human normativity confirmation. The interface displays and exports only positive ambiguity predictions, and optional local Qwen explanations are restricted to those results. Uploaded document text remains local and is not sent to a remote service. This conservative gate can omit genuine normative clauses that do not use explicit BCP~14 terms; scores are not calibrated probabilities, explanations are hypotheses rather than evidence, and predictions are not adjudicated ambiguity judgments.

\subsection{Consecutive-revision alignment}

For revisions $t-1$ and $t$, bidirectional retrieval first searches corresponding and nearby sections, followed by a bounded global fallback. Candidate score $s(i,j)$ combines semantic, lexical, structural, positional, block-type, and protected-token evidence:
\begin{equation}
s(i,j)=\sum_{k} w_k s_k(i,j),
\end{equation}
where semantic and lexical similarity each receive weight 0.38 in the semantic pilot, structure 0.12, and position, block compatibility, and protected-token evidence 0.04 each. Distinctive exact anchors are locked only when supported by section structure. One-to-one components use bipartite assignment with unmatched choices. Competing split and merge candidates of at most three adjacent clauses use a mixed-integer program with non-overlap constraints. Moves require section correspondence or reliable anchor inversions; close alternatives remain \textsc{Uncertain}.

MiniLM embeddings are computed from direct tokenizer-ID windows, avoiding text reconstruction between tokenization stages. The TLS coverage pilot aligns 30 documents across 29 consecutive pairs: 52,137 clause-version occurrences produce 52,953 relationships, including 4,452 modified, 2,356 inserted, 2,025 deleted, 261 split, 260 merged, 1,808 moved, and 5,199 uncertain relationships. Fig.~\ref{fig:alignment-counts} visualizes these counts. They establish pipeline coverage, not alignment accuracy: the stratified 150-link review sample has not been adjudicated, so link precision and recall are intentionally unreported. Revision links are not model features in the transformer experiment reported below.

\subsection{Temporal and leakage controls}

For a clause in revision $t$, revision features may depend only on revisions $\leq t$. Later drafts, RFC text, later errata, undated evidence, annotation metadata, and model votes are rejected by a feature guard. RFC endpoints are available for offline correspondence research but not for draft-stage prediction. Family grouping blocks related clauses from crossing train and evaluation roles. Exact normalized cross-partition target overlap is zero in the current artifact. Fitting-side exclusions additionally cover near duplicates, shared lineages, BCP~14 skeleton conflicts, and target-as-context reproduction.

\section{Reference Labels and Partitions}

\subsection{Operational annotation reference}

Candidate clauses were assembled from eleven draft-family review sets after lineage deduplication. Three local models (Gemma~3~27B, GPT-OSS~20B, and Qwen3~32B) independently supplied binary or uncertain decisions. Two agreeing valid votes form the consensus; unanimous consensus is marked high-confidence and a two-of-three decision medium-confidence. Rows without a strict two-vote majority remain uncertain rather than being forced into the negative class. The training export excludes uncertain candidates, rationales, later-revision evidence, and errata-derived features.

The latest matched classical/heuristic comparison uses all 2,425 resolved rows in \texttt{final\_annotation\_ready.csv}: 160 positive and 2,265 negative clauses across eleven families. This rerun includes TCP and DNS and therefore supersedes the earlier 2,406-row classical result still described in the revision-feature summary markdown; that summary is stale relative to the current metrics manifests. Earlier Qwen/hybrid studies use a frozen 2,424-row annotation-ready source and its 2,142-row, 126-positive nine-family development cohort, with TCP (131 rows, 5 positives) and DNS SVCB/HTTPS (151 rows, 17 positives) excluded. An earlier target-only transformer study used a hash-pinned subset of 2,125 rows (136 positives) after family and label-blind fitting exclusions. The updated \texttt{final\_annotation\_ready.csv} contains 2,055 model-agreement, 270 manual-conflict-verdict, and 100 \texttt{human\_review\_user\_confirmed} records, including resolution of the previously unresolved \texttt{item\_id=2161}. Its transformer development cohort contains 2,143 rows (138 positives) across nine families. The 100 reviewed cases were selected from historical OOF errors, so this updated cohort is error-selection biased and is not an independent or population-representative gold test. The updated DeBERTa follow-up compares focal loss, partial fine-tuning, and their rank ensemble on the same updated cohort; the reported analysis repair reuses the parent experiment's validated predictions and does not create independent evaluation evidence. Labels throughout this report are an \emph{operational reference}, not independently double-annotated expert gold; metrics quantify agreement with a particular annotation artifact rather than universal ambiguity-detection accuracy.

\subsection{Annotation disagreement audit}

The annotation reference is noisy and model-dependent. In the earlier 2,546-row consensus snapshot, 435 of 455 positive rows (95.6\%) had a 2--1 vote split; only 20 were unanimous positive. Among negative rows, 1,325 of 2,091 (63.4\%) had a 2--1 split. This corresponds to an implied weighted positive share of 14.3\%, compared with 17.9\% unweighted. A later leave-one-model-out audit on vote-eligible subsets measured pairwise Cohen's $\kappa$ of 0.113 (Gemma/GPT-OSS), 0.017 (Gemma/Qwen3), and 0.046 (GPT-OSS/Qwen3), despite raw agreement ranging from 0.370 to 0.792. Agreement-conditioned tiers were structurally extreme: the unanimous tier had perfect leave-one-out AP by construction, whereas the medium tier was highly imbalanced and often too small or single-class for stable estimates. The held-out-model vote APs were 0.0157 for Gemma, 0.1047 for GPT-OSS, and 0.3825 for Qwen3 on their respective eligible subsets. Separately, the consensus-trained predictor's AP changed from 0.275 when scored against consensus to 0.737 against Gemma labels, 0.299 against GPT-OSS labels, and 0.028 against Qwen labels on the associated diagnostic snapshot. This target-sensitivity analysis is not a ranking of annotator quality; it reinforces that scores depend strongly on which model's decisions define the target. These audits do not identify which annotator is correct; they show that the consensus target itself is uncertain. A proposed vote-weighted model was not run because the pre-established stop rule triggered when most rows in both classes had weight 0.5.

\section{Models and Experimental Protocol}

\subsection{Evaluation measures}

For scores $p_i$ and labels $y_i$, the primary ranking metric is average precision (AP), computed as the stepwise precision-weighted increase in recall. Repository reports historically call this ``PR-AUC''; here we use the more precise name AP. Its no-skill reference is the positive prevalence, 0.064 in the evaluated development cohort. We also report ROC-AUC, precision, recall, $F_1$, $F_2$, balanced accuracy, confusion counts, and retrieval at fixed review budgets. Threshold-free rankings are primary because the appropriate operating point depends on reviewer capacity and the relative cost of missed ambiguity.

Uncertainty for the latest transformer study is estimated with 2,000 bootstrap resamples of the nine RFC families. These intervals represent sampling variation across the observed families; they do not include model-training variability, since the newest study has one seed.

\subsection{DeBERTa variants and rank ensemble}

Inputs contain only the target clause, with a maximum length of 256 tokens and deterministic head--tail truncation; the experiment reports no target truncation. Both models use five epochs, AdamW, learning rate $10^{-5}$, weight decay 0.01, a linear schedule with 10\% warmup, batch size 8, FP32, deterministic execution, and seed 2718. The focal model uses $\gamma=2$ and fitting-side class weights ($\alpha_0=1$, $\alpha_1=N_{-}/N_{+}$):
\begin{equation}
\mathcal{L}_{\mathrm{focal}}=-\alpha_y(1-p_y)^\gamma\log p_y.
\end{equation}
The partial model uses weighted cross-entropy and trains only layers 8--11, the pooler, and classifier.

For the ensemble, each method's empirical cumulative distribution function is fit on the corresponding fitting-side inner OOF scores. The two percentile ranks are averaged with equal weight and applied to the untouched outer-fold predictions. The resulting value is a ranking score, not a calibrated probability.

\subsection{Classical machine learning and heuristic}

The latest classical/heuristic comparison uses 2,425 rows, with 160 positives (6.60\%) from 11 draft families. Models are evaluated using three-fold stratified group cross-validation, keeping draft-family groups intact; feature scaling, TF--IDF vocabulary, and feature selection are fitted within each training fold. The logistic-regression model uses 25 engineered clause features concatenated with word unigram/bigram TF--IDF, class-balanced L1 regularization, and $C=0.5$. The complete recorded model grid also evaluates logistic regression, Linear SVM, and random forest with TF--IDF, frozen 384-dimensional MiniLM embeddings, TF--IDF plus embeddings, engineered-plus-TF--IDF inputs, and engineered-plus-TF--IDF with twelve label-free revision features. These revision features summarize the two preceding draft transitions (the target's $t-1\!\to t$ change and, where available, the predecessor's $t-2\!\to t-1$ change); matching is constrained to drafts available no later than the target revision. The full results are in Table~\ref{tab:classical}. This latest all-family run includes TCP and DNS, so it is grouped OOF development evidence rather than the untouched reserved-family evaluation proposed originally.

The fixed heuristic is not trained on labels. It assigns hand-set points to conditional clauses lacking exception markers, deictic expressions, mixed BCP~14 modal levels, subjective terms, and exceptions; numeric bounds and explicit target references subtract points. The score is clipped to $[0,9]$, normalized by nine, and thresholded at 0.4. Its rules and threshold are fixed rather than fit per fold. We report average precision from OOF scores and threshold metrics at the recorded operating threshold; the heuristic is a transparent low-cost baseline, not a learned classifier.

\subsection{Earlier family-held-out classical study}

The repository also contains a distinct earlier study with a nine-family leave-one-family-out protocol, 2,540 evaluated clauses, and 17.8\% positive prevalence. Its combined target TF--IDF/engineered baseline (E0) has pooled OOF AP 0.291 (95\% bootstrap interval 0.260--0.335). Frozen MiniLM and BGE-small representations with engineered features reach AP 0.246 and 0.245, respectively. Simple one-revision predecessor signals yield AP 0.168 and 0.165. These results provide historical methodology context only; their cohort and labels differ from the latest 2,425-row ML/heuristic comparison and from the transformer/LM cohorts.

\subsection{Language-model and hybrid study}

We also report the repository's separate Qwen3-32B development study~\cite{yang2025qwen3}, which uses the frozen \texttt{final\_annotation\_ready.csv} label artifact: 2,142 clauses from nine families, including 126 positives (5.88\%). It uses the five family-grouped outer folds defined for that artifact and is separate from the updated 2,143-row reviewed-label DeBERTa cohort. The model is a local quantized Qwen3 32B inference model; V1 and V2 update no model parameters. V1 compares zero-, four-, and eight-shot prompts, selecting demonstrations from fitting families and scoring the \texttt{yes}/\texttt{no} alternatives from native token log-probabilities. V2 tests stricter prompts with 8, 16, or 24 fold-safe demonstrations, including prevalence-aware class proportions, and estimates threshold operating points by cross-fitting. V3 combines frozen Qwen zero-shot scores with a nested, target-only word/character TF--IDF logistic classifier; its regularization and blend weight are chosen using inner-fold predictions. V4 combines the V3 score with frozen MiniLM semantic representations of the target and local context using the Sentence-BERT bi-encoder paradigm~\cite{reimers2019sbert}. The semantic classifiers use class-balanced logistic regression ($C=0.03$); the 0.80/0.10/0.10 V3/target/context combination was selected on development data. V3 and V4 are supervised hybrid models, not parameter-fine-tuned LLMs. An additional exploratory comparison maps each component's scores to empirical within-cohort percentile ranks, averages the ranks with equal weight, and evaluates only the shared label-compatible rows; neither weights nor a classification threshold are fitted. This comparison reuses OOF predictions from different label snapshots and is not an independent test. Results for the Qwen study and cross-model rank ensemble are reported in Section~\ref{sec:llm-results}.

\subsection{Nested operating points}

Threshold selection is performed only on the fitting side. For each outer fold, three family-disjoint inner folds estimate method-specific thresholds. The policy maximizes recall subject to minimum fitting precision in $\{0.20,0.30,0.50\}$, breaking ties by higher precision and then higher threshold. Infeasible targets remain missing; they are not replaced by an always-positive rule. Precision targets are objectives on inner data, not guarantees on a held-out family.

\section{Revision-Feature Implementation}

The current classical experiment adds twelve compact numerical features to the engineered-plus-TF--IDF representation. H0 describes the immediate $t-1\!\rightarrow t$ transition and H1 describes $t-2\!\rightarrow t-1$ after following the H0 predecessor. Each tier includes predecessor availability; unchanged, modified, and moved indicators; and match-based and lexical change distances. The feature loader reads only \texttt{item\_id}, \texttt{record\_id}, and \texttt{family\_id} from the annotation identity key. It rejects duplicate identities, unexpected matcher versions, and document mismatches. Labels, candidate-source fields, votes, rationales, future drafts, final-RFC endpoints, and errata are excluded. Numerical scaling is fit separately on each training fold, and every final manifest records the feature schema plus hashes of all matcher caches.

\section{Model and Artifact Interfaces}

The classical runners share one feature-construction interface so that logistic regression, Linear SVM, and random forest receive identically ordered inputs. Every experiment writes fold metrics, OOF scores, a metrics summary, a provenance manifest, raw revision features when used, and a final development model. Plot generation discovers saved metrics, checks cohort compatibility, and compares only runs with the same row count, positive count, and fold composition. The report uses the OOF artifacts for evaluation; final models fit on all development rows are retained only for downstream prototype use.

\section{Local Review Prototype}

The local interface is a human-in-the-loop inspection tool. It parses a selected RFC, applies the saved classical model to eligible BCP~14 clauses, and presents ranked clauses with surrounding text and filtering controls. Optional local-Qwen explanations are requested only for selected results and do not alter the classifier score. This separation prevents generated explanations from silently becoming prediction features. The interface does not implement an autonomous publication gate, and the current threshold is not deployment-calibrated.

\section{Implementation Choices and Reproducibility}

Python, pandas, SciPy, scikit-learn, PyTorch, Hugging Face Transformers, and sentence-transformers provide the main implementation stack. Fixed seeds, immutable input manifests, SHA-256 hashes, family-level fold assignments, and serialized preprocessing objects support repeatability. Cached local-model outputs reduce nondeterministic or costly reruns. The repository nevertheless does not constitute a completely self-contained public artifact: private annotation exports, model weights, and some large local runs are intentionally absent, and a fresh clone cannot reproduce every table without those inputs.

\chapter{Discussion}

\section{Answers to the Proposal Research Questions}

\subsection{RQ1: Draft-Stage Detection Effectiveness}

The experiments show that contemporaneous draft text contains useful ranking signal against the project's operational reference. On the latest matched classical cohort, engineered features plus TF--IDF reach AP 0.3584 with a Linear SVM at 6.60\% prevalence. On the separate nine-family reviewed-label transformer cohort, the DeBERTa rank ensemble reaches AP 0.6736 at 6.44\% prevalence and retrieves 19 of 20 reference positives in its pooled top-20 ranking. These estimates use only information available at the evaluated draft revision and isolate draft families across folds. The answer is nevertheless qualified: the cohorts are candidate-enriched, labels are not independent expert gold, the updated cohort contains 100 error-selected confirmations, family intervals overlap, and the latest classical rerun has already consumed the proposed TCP/DNS holdouts. RQ1 is therefore answered as a development-stage feasibility result, not as validated prospective accuracy.

\subsection{RQ2: Revision History, Cross-References, and Calibration}

The controlled classical ablation does not support a consistent revision-feature improvement. Revision features change AP by $-0.0081$, $-0.0012$, and $-0.0015$ for logistic regression, SVM, and random forest; corresponding $F_2$ changes are $0.0000$, $+0.0110$, and $+0.0227$. Earlier predecessor-only models also remained near or below their cohort prevalence. Cross-reference counts are included among engineered features, but no isolated cross-reference ablation was completed. The revision experiment records no Brier score, expected calibration error, or calibration curve. Thus RQ2 is partly answered: the tested contemporaneous revision features do not improve ranking AP in the latest rerun, while their thresholded $F_2$ effect is model dependent and the cross-reference-specific and calibration parts remain unresolved. Hypothesis H1 is not supported as a general claim.

\subsection{RQ3: Comparison of Model Families}

Table~\ref{tab:rq3-comparison} summarizes the evidence without presenting incompatible cohorts as a common leaderboard. Fine-tuned DeBERTa provides the strongest observed ranking result in its own updated cohort. Classical engineered-plus-TF--IDF models provide competitive, inexpensive, and auditable rankings in their cohort. Direct Qwen prompting provides high recall but low precision, and its fitted lexical--semantic hybrid improves ranking within the Qwen study. The heuristic is most transparent but substantially weaker. Reproducibility is strongest for deterministic rules and classical pipelines and weaker for one-seed transformer and hardware-dependent local-LLM runs. Review-budget and referral analyses are available, but a common latency, energy, token-cost, or monetary-cost benchmark was not recorded. RQ3 is therefore answered for effectiveness and workload only under separate protocols; the quantitative latency/cost comparison remains incomplete.

\subsection{RQ4: Hybrid Routing and LLM-Call Reduction}

The implemented V3/V4 hybrids combine cached Qwen scores with fitted lexical and semantic components; they are score-level hybrids rather than the proposal's conditional router. Because Qwen was evaluated for the cohort before combination, these experiments do not demonstrate fewer LLM calls. The separate referral analysis estimates how many clauses a classifier would send to human review at target recall, but it does not measure conditional LLM invocation. The fixed three-model rank ensemble similarly uses already-computed scores. RQ4 is therefore not answered in the intended causal comparison, and hypothesis H2 remains untested. A valid experiment must freeze a routing policy, count avoided LLM invocations, and compare effectiveness, latency, and cost against an LLM-only run on the same untouched cohort.

\subsection{RQ5: Evidence and Explanation Quality}

The local application can request optional Qwen explanations for selected clauses, and the prompting formats can emit rationales or structured fields. However, the repository contains no completed expert study of evidence-span correctness, ambiguity-subtype accuracy, rationale--label agreement, hallucinated-reference rate, usefulness, or clarity. Explanation text is not used as a prediction feature and is presented as a hypothesis to reviewers. RQ5 and hypothesis H3 therefore remain unanswered. This negative finding is important: classifier effectiveness cannot be used as a proxy for explanation faithfulness.

\section{Interpretation of the Development Results}

The updated family-isolated OOF scores indicate that clause text contains a useful ranking signal relative to the operational labels. Among the three methods evaluated on this same updated cohort, the rank ensemble has the highest observed AP and top-budget retrieval, but its family-cluster interval overlaps those of focal loss and partial fine-tuning. This ordering is descriptive, not a significance result. A second run across multiple seeds and an independently sampled, expert-adjudicated evaluation set are needed before claiming a reliable winner.

The separate language-model study shows a different pattern: direct Qwen prompting gives high recall at low precision in V1, while the stricter V2 prompt substantially reduces recall and AP. Adding a nested lexical classifier in V3 and frozen semantic features in V4 improves AP within that study's development cohort. These are adaptive comparisons with an operational label reference; they neither establish that LLMs outperform DeBERTa nor support direct numeric comparison across the two cohorts.

Ranking is more defensible than treating the model as a binary gate. The selected inner-fold thresholds optimize a precision constraint on fitting data, but pooled OOF behavior and family-specific outcomes show that the constraint does not transfer uniformly. A user-facing system should present clauses for expert review, expose source revision and surrounding context, and avoid claims that a low score certifies correctness.

On the separate classical/heuristic cohort, engineered features combined with TF--IDF produced stronger AP than the fixed heuristic and the tested embeddings-only baselines. This supports the value of lexical and explicit clause cues for ranking within that cohort, but the high-recall logistic operating point has low precision and does not remove the need for human review. The earlier LOFO results offer additional historical evidence for sparse lexical features, but differ in annotation, cohort, and validation setup. Frozen embeddings and basic predecessor features did not improve the matched LOFO baseline in the recorded feature setup; this is not evidence that semantic or temporal context is universally unhelpful. These classical and Qwen/hybrid results were not evaluated on the updated 2,143-row transformer cohort; cross-study AP values must not be treated as a unified model leaderboard.

The twelve newly evaluated revision features produce small changes in the matched classical cohort: AP decreases slightly for all three classifiers, while $F_2$ is unchanged for logistic regression and increases for SVM and random forest. The fixed three-component rank ensemble reaches AP 0.4619 on the label-compatible 2,097-row intersection, but the classical predictions were trained using earlier labels while V4 and the combination were developed on the intersection. Its narrow AP difference over the classical component is descriptive, not evidence of complementary generalization or a fair head-to-head win.

Across the older DeBERTa ablations, soft-target training did not improve the primary fold-balanced selection statistic and local context reduced it. A lower soft-target referral estimate at a fixed recall objective is a potentially useful future routing hypothesis, not evidence that it improves detector quality. The updated reviewed-label transformer run changes the operational labels and effective cohort relative to the earlier target-only study. The 100 human-confirmed cases were selected using historical OOF errors, and the associated family-bootstrap intervals overlap; consequently, the observed ensemble gain is not independent confirmation and may reflect the error-enriched evaluation design.

Revision alignment provides useful lineage and leakage-control infrastructure, but its pilot has not been evaluated against adjudicated gold links and its outputs are not used as predictive features in the transformer study.

\section{Deployment Interpretation}

The repository includes a local RFC-review browser prototype that currently applies the saved engineered-feature/TF--IDF logistic model only to clauses classified as normative by explicit uppercase BCP~14 keywords after parser exclusions. The newer transformer ensemble is presented as a research candidate, not wired for live single-RFC scoring. Lowercase-modal and section-context candidates are omitted rather than manually confirmed; consequently, RFCs lacking explicit BCP~14 terms may receive no predictions. Optional local Qwen explanations are restricted to selected flagged results and do not affect predictions. This conservative routing may reduce recall and is not a comprehensive normative-clause detector. The prototype is not an evaluated deployment system: the active model's score is not a calibrated probability and its saved threshold is not deployment-validated; generated explanations remain hypotheses. Automatic rejection or publication certification is inappropriate. The top-50 results in Tables~\ref{tab:reviewed-topk} and the earlier transformer analysis are retrospective development diagnostics, not estimates of production precision or guaranteed reviewer yield.

\section{Reproducibility and Governance}

The experiment records hashes for the authoritative label source, effective dataset, model snapshot, folds, configuration, and derived predictions. The earlier source/effective-dataset SHA-256 values begin \texttt{8e395e83087c} and \texttt{19364a405048}; the updated reviewed-label source/effective-dataset values begin \texttt{8ffa654c2c40} and \texttt{4e20a2571bfe}. Full hashes remain in the experiment manifests. The model snapshot is used offline, and the experiment manifest pins seed, tokenizer, and training configuration. The analysis-repair version validates and reuses the parent experiment's 40 prediction artifacts; it does not retrain models or constitute a second evaluation. Code and selected aggregate tables are available in the project repository~\cite{artifact2026}; private annotation exports, row-level outputs, model weights, and large run directories are intentionally not part of a public release. The source annotation files required to reproduce the model results are therefore not present in a fresh repository clone, and the current result tables alone are insufficient for full independent reproduction.

\section{Threats to Validity}

\subsection{Construct validity}

The binary reference operationalizes ambiguity through a particular rubric and annotation workflow. It does not exhaust RFCScope's seven subtypes, and AI-supported labels can reproduce shared model biases. Qwen3 contributed to annotation support, making the Qwen agreement analysis non-independent of label construction. The manual-conflict process is not equivalent to blinded, independent, double expert annotation. These issues limit claims about the real-world construct of ambiguity.

Candidate selection is also enriched rather than population-random. Metrics estimate performance on the reviewed candidate cohort, not on every sentence or clause in all Internet-Drafts. AP and prevalence therefore must not be transported to the full IETF corpus.

The multi-model consensus is not a statistically independent annotation panel. Low pairwise kappa and the large proportion of two-to-one positive votes indicate material uncertainty, while the model-target sensitivity analysis shows that the same predictions can score very differently under alternative annotator targets. No experiment in this paper estimates human inter-annotator reliability against an adjudicated expert gold set.

There is also an unresolved provenance/count discrepancy in the candidate exports: the evaluated LOFO artifact contains five errata-derived rows, all negative and all TLS, whereas an earlier progress report cited 121 errata positives and 242 TLS records. The corpus-level count of 31 verified technical errata refers to source documents, not positive clause labels, and does not reconcile those candidate-export counts. Until the row-level source definition is reconciled, errata-derived candidate results must not be interpreted as a comprehensive errata evaluation.

\subsection{Internal validity}

Family splits, fitting-only preprocessing, inner-only thresholds, and exact/near/lineage exclusion reduce leakage. They cannot eliminate pretraining contamination: modern encoders may have seen historical RFCs or drafts. The experiment uses a single seed, and family bootstrapping does not account for training variance. Architecture and analysis choices were made within the wider development process; the reported OOF study should therefore be interpreted as development evidence, not a pre-registered confirmatory benchmark.

The updated 100-case human-confirmed annotation subset was selected from historical OOF errors. It is therefore subject to error-selection bias; evaluating models on these cases or their families cannot provide an unbiased estimate of generalization or improvement. The reported updated-cohort OOF metrics are complete, but are not independent confirmation: the analysis-repair step validates and reuses predictions from the parent training run. A future assessment requires an independently sampled, untouched evaluation set, preferably spanning families absent from model selection.

\subsection{External validity}

Only nine families contribute scored rows to the updated transformer development study, and QUIC/HTTP dominate row counts. The smallest families cannot independently support meaningful AP estimates. TCP and DNS are absent from that transformer study, but their labels were consumed by the latest all-family classical rerun; consequently, they are neither transformer evidence nor untouched project-level tests. Routing protocols with historical drafts outside the current cohort, standards from other organizations, and newly authored drafts after the models' pretraining period are also untested.

\subsection{Alignment validity}

The TLS alignment run has deterministic audits but no reviewed gold links. Alignment confidence is rule-based and uncalibrated. Split/merge grouping, move heuristics, and long-clause pooling are approximations. Accordingly, correspondence statistics are engineering coverage, not evidence of alignment accuracy, and automatic revision relationships are not used as ground-truth ambiguity labels.

\section{Ethical and Practical Considerations}

All source standards and errata are public technical documents. The principal risk is epistemic rather than personal: an incorrect ``ambiguous'' flag could waste reviewer time or unfairly characterize an author's work, while a false negative could create unwarranted confidence. The system must expose uncertainty, provenance, and its non-certification role. Generated explanations should be treated as hypotheses and checked against the exact contemporaneous text. Final evaluation should be reported once, including negative outcomes, and the sealed set should not be recycled for iterative tuning.

\chapter{Conclusion and Future Work}

\section{Summary of Achievements}

\system{} combines corpus acquisition, structural parsing, normative-clause segmentation, revision alignment, lineage-aware candidate construction, AI-assisted consensus annotation, and grouped classical/transformer/LLM evaluation. The project reports correspondence coverage separately from ambiguity classification and excludes later revisions, RFC endpoints, errata, annotation votes, and rationales from model features. Results span several annotation snapshots and protocols. In the latest updated-label transformer study, focal loss, partial fine-tuning, and their equal-weight fitting-side ECDF ensemble were evaluated on the same 2,143-row, nine-family cohort (138 positives): AP was 0.5823, 0.5761, and 0.6736, respectively. The family-cluster intervals overlap, only one training seed was run, and 100 human-confirmed records were selected from historical OOF errors; the observed ensemble lead is therefore descriptive and potentially affected by error-selection bias. Other studies reported AP 0.0603 for weighted DeBERTa on an initial low-prevalence cohort; 0.291 for TF--IDF-plus-engineered features in an earlier nine-family LOFO study; 0.3584 for the latest all-family classical SVM; 0.3715 for a nested DeBERTa ensemble; and 0.1960 for eight-shot Qwen and 0.3252 for its V4 lexical/semantic hybrid. A fixed three-model rank ensemble reached AP 0.4619 on a label-compatible intersection, but remains exploratory because its component predictions have mismatched label provenance. These cross-study values are not a unified leaderboard. The local review GUI currently runs the saved classical logistic-regression artifact; the newer transformer ensemble is a research candidate, and optional local Qwen explanations do not change predictions. The GUI and all model outputs remain unvalidated for independent deployment. The attempted second-generation annotation panel produced no corpus labels because it was blocked at preflight.

The strongest conclusions are methodological rather than deployment claims: family-isolated evaluation is feasible; target text and transparent lexical/engineered features provide useful ranking signal against the operational reference; the tested revision features do not improve ranking AP in the latest matched rerun; and performance depends on model family, data snapshot, evaluation protocol, and annotation target. The low inter-model agreement, adaptive development comparisons, overlapping family uncertainty, single-seed transformer results, error-selected human review, absence of an independent expert gold set, and loss of the proposed TCP/DNS holdouts prevent a claim of validated ambiguity-detection accuracy. Annotation sources and large run artifacts are also not included in a fresh clone.

\section{Future Work}

Before making a deployment or final-generalization claim, the project should: (1) independently double-annotate and adjudicate a stratified expert sample; (2) repeat the selected transformer configurations across multiple seeds; (3) implement the proposal's actual conditional LLM router and record calls, latency, energy or token use, and monetary cost against a same-cohort LLM-only baseline; (4) isolate cross-reference features and add Brier score, expected calibration error, and reliability diagrams; (5) conduct blinded expert assessment of evidence spans, subtype assignments, rationale faithfulness, hallucinated references, usefulness, and clarity; (6) validate revision links, including split/merge relationships, against a reviewed alignment sample; and (7) preregister and preserve a new genuinely untouched evaluation, such as unseen draft families or later time-sliced revisions, because TCP and DNS have already entered the classical evaluation. Until those steps are complete, the appropriate claim is a reproducible, promising development-stage review aid---not a published-standard oracle or autonomous quality gate.

Run the following commands from the repository root. They reproduce the current revision-augmented classical runs and comparison plots when the tracked annotation and matcher-cache inputs are present.

\begin{verbatim}
python -m models.classical.train_annotation_engineered_tfidf_revision
python -m models.classical.annotation_classifier_experiments \
  --classifier linear_svm --feature-mode engineered_tfidf_revision
python -m models.classical.annotation_classifier_experiments \
  --classifier random_forest --feature-mode engineered_tfidf_revision
python -m models.classical.plot_annotation_results
python paper/generate_report_figures.py
\end{verbatim}

The principal outputs are stored in:
\begin{itemize}[nosep]
    \item \path{results/ML/v2_engineered_tfidf_revision/};
    \item \path{results/ML/additional_classifiers/}; and
    \item \path{results/ML/figures/}.
\end{itemize}
Each revision run includes OOF predictions, fold metrics, raw revision features, a final development model, and a provenance manifest.

\section{Local Review Application}

After restoring the approved classical model artifact described in the repository README, start the local application with:

\begin{verbatim}
python -m gui.app
\end{verbatim}

The interface binds to \texttt{http://127.0.0.1:8765/}. A reviewer can upload a rendered RFC text file, inspect positive-ranked clauses, filter by section, download results, and optionally request local explanations for at most five selected clauses. Scores are not calibrated probabilities and results require human verification.
